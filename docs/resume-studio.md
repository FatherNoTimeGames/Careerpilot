# Résumé Studio

Implemented as the first Prototype 2 checkpoint, before application preparation. All document processing happens locally; no document is sent to an AI API or external service.

## Owner access

Run the installation and initialization steps in README.md. Initialization creates an owner password at `owner-password` beside the selected database (0600), retaining any existing password. Read it privately on the server to sign in as `careerpilot`. Alternatively provide a strong `CAREERPILOT_PASSWORD` through your host's protected environment configuration. Values are never printed, committed or put in saved setup instructions. Studio refuses unauthenticated storage even on loopback. Production still requires private HTTPS hosting and encrypted backups; this milestone does not deploy Sites.

## Workflow

1. In **Résumé Studio**, upload a PDF or DOCX. The exact original is saved before extraction, with its SHA-256 and import timestamp. Download it under Original documents. Invalid/unreadable documents retain the original and display an error; they never create verified facts.
2. Review the extracted text, then choose **Review extracted entries in profile**. Grouping and recognized date ranges are suggestions, not confirmation. Correct sections, text, dates and evidence. Mark each checked entry Confirmed by me; leave uncertainty Pending or Inferred. New information can be added directly without another upload. Editing content in the UI resets that entry's confirmation.
3. Save and verify the profile revision. Confirmation is an owner attestation, not independent credential verification. Missing sections/dates, ongoing roles, duplicate content and contradictory dates are flagged. Contradictory dates block verification. Nonconfirmed entries remain excluded from résumé versions. Saving later edits creates another immutable profile snapshot and requires verification again.
4. Create a named résumé version from selected confirmed facts. Optionally associate a real saved job and source original. Fact selection provides job-specific emphasis without copying unverified job requirements into your profile. This is résumé tailoring, not authorization for full application preparation.
5. Use the manual side-by-side original/revised editor. Explain wording changes. Deterministic checks flag repeated words, spacing, long/repetitive entries and generic phrases; new numerical or credential language blocks export until it is verified in the profile. These checks are **not semantic truth verification or comprehensive grammar/AI proofreading**. The owner must proofread and confirm that changed wording adds no qualifications. `resume_revision.py` is the replaceable AI boundary; no approved AI provider is configured, and automated rewriting is explicitly unavailable.
6. Choose **Check & render PDF preview**. PDF and DOCX text is round-tripped against the approved-source content; every PDF page is rendered locally and checked for nonblank content within safe margins. Inspect all displayed pages (tap for full-size images) for readable, complete layout. Generation alone does not approve a version.
7. Explicitly acknowledge factual/proofreading and visual-layout review, then approve that version. Only approved exports can be downloaded. Approved versions and their generated bytes are immutable; later profile edits flag older versions but never silently rewrite them. Drafts based on an older profile cannot be approved; recreate them from the verified current profile.
8. **Make master résumé** is a separate confirmation. It preserves the prior version and rejects stale replacement requests. Select an approved version for a job independently; the application records its exact version ID without changing the job's application status or granting preparation/submission authority.

## Format and processing limits

- Up to 5 MB per PDF/DOCX and 20 PDF pages. DOCX archives are bounded by entry count and expanded size; macro-enabled documents are refused. Parsed text is limited to 60,000 characters and organized suggestions to 100 entries; limits produce warnings/errors and retain the original. Extraction uses a subprocess with 20 CPU seconds, 1 GB address space and a 35-second wall timeout on Linux.
- Text-based PDFs and DOCX paragraphs/tables are supported. Scanned/image-only or password-protected PDFs need a readable replacement or manual entry; there is no OCR. Complex columns or unusual headings can be grouped incorrectly. Always compare extraction with the original.
- Sections cover contact, summary, professional employment, education, skills, personal technical experience, accomplishments and certifications. Dates support YYYY, YYYY-MM and present; unclear dates remain source text until corrected. Up to 100 profile facts with 5,000 characters each.
- Export uses selectable embedded sans-serif text, standard headings, a single column and conventional margins. Unsupported font characters block export instead of disappearing silently. No layout can guarantee acceptance by every ATS. DOCX content was round-trip tested, but Microsoft Word rendering is not available on this host.
- No OCR, automated AI revision, full application packages, email or application submission is implemented. No paid API or subscription was added.
- Sensitive originals, text, facts, source references, versions, images and exports stay in the private SQLite database. They are excluded from Git and static assets. Logs use record IDs without document/profile contents. The database is not encrypted by the application; protect the host disk and backups. Imported documents are not executed.

## Validation

`python3 -m unittest discover -s tests -v` exercises import, preservation, uncertain facts, contradictions, stale edits, version immutability, approval boundaries, private downloads and multi-page export integrity, alongside all discovery tests.

Optional browser regression (Playwright 1.62.0 and Chromium were available in this environment):

```sh
PYTHONPATH=. python3 tests/browser_studio.py
```

Set `CAREERPILOT_CHROMIUM` if Chromium is installed elsewhere. The check uses a temporary database and synthetic résumé, not the live profile. It exercises a 393-pixel mobile viewport, including import, verification, navigation with unsaved wording, comparison, preview, approval, download, master replacement, job selection and reload. Browser tooling is not a runtime dependency.
